# 記帳模型：日期欄位 + 類別標準化設計

## 目標
1. 在 tool call 中加入 `date` 欄位，讓模型能從自然語言中辨識時間
2. 標準化類別命名（去重疊），並擴充新類別
3. 直接修改 raw dataset（train/test .jsonl），不更動資料載入流程

---

## 1. 日期欄位

### 格式
- ISO 8601，僅日期精度：`YYYY-MM-DD`
- **Compressed 格式**：`[DATE]2026-07-20`
- **JSON 格式**：`"date": "2026-07-20"`

### 系統提示詞
- 每個 system prompt 開頭加入：`今天是 2026-07-20。`
- 訓練/推論使用一致的參考日期 2026-07-20

### 時間詞 → ISO 日期轉換規則

| 輸入文字 | 轉換結果 |
|---------|---------|
| 今天 | 2026-07-20 |
| 昨天 | 2026-07-19 |
| 前天 | 2026-07-18 |
| 明天 | 2026-07-21 |
| 這個月 | 2026-07 + 隨機日 |
| 上個月 | 2026-06 + 隨機日 |
| 下個月 | 2026-08 + 隨機日 |
| 這週 | 2026-07-20 |
| 上週 | 2026-07-13 |
| X月Y號/日 | 2026-X-Y |
| 僅提及月份（如 12月的薪水） | 2026-12 + 隨機日 |
| 早上/中午/晚上/剛剛 | 隨機日期 |
| 無時間詞 | 隨機日期 |

優先級：明確日期（X月Y日）> 相對詞（昨天/上個月）> 隨機日期
隨機日期範圍：參考日期 ±3 個月（2026-04-20 ~ 2026-10-20），每筆 seed = sample index，結果可重現

### 新增 Special Token
- `[DATE]` 加入 tokenizer

## 3. 執行步驟

### Step 1: Tokenizer
- `[DATE]` 加入 `SPECIAL_TOKENS`
- `format_compressed_record()` 新增 `date` 參數

### Step 2: validate_json.py
- `extract_tool_call()` 對 `[DATE]` 解析
- `validate_record()` 不做 date 必填檢查

### Step 3: 轉換腳本（直接修改 raw）
- 讀取 `dataset/train_strata.jsonl` + `test_strata.jsonl`
- 對每筆 sample：
  1. 標準化類別名稱
  2. 解析 user query 時間詞 → ISO 日期
  3. system prompt 開頭插入日期前綴
  4. tool call 加入 date 欄位（JSON/compressed 皆支援）
- 寫回原檔案

### Step 4: 重新訓練
- 同 champion 參數：`--format compressed --epochs 8 --lr 2e-4`
- 只換 dataset

### Step 5: Demo 更新
- system prompt 改為含日期的版本
